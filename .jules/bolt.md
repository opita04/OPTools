## 2025-04-14 - Process.GetCurrentProcess() Allocation Overhead
**Learning:** In .NET, `Process.GetCurrentProcess()` does not return a cached instance. It allocates a new `System.Diagnostics.Process` object and makes an underlying native API call every time it is invoked. Inside tight loops (like iterating over thousands of system handles during memory/lock enumeration), this leads to excessive GC pressure and CPU overhead.
**Action:** Always prefer direct P/Invoke calls (`[DllImport("kernel32.dll")] public static extern IntPtr GetCurrentProcess();`) when the process handle or ID is needed inside tight, performance-critical loops in C# code.

## 2025-05-18 - Directory Traversal and Enumeration side-effects
**Learning:** While `EnumerateFiles` and `EnumerateDirectories` improve performance by reducing large object allocations via lazy evaluation, applying them over directories that are actively being modified (such as deleting files or directories as in `SystemCleaner.cs` or `FolderCleaner.cs`) leads to undefined behavior. The enumerator can skip files or throw exceptions because the file system index changes during iteration. The `GetFiles`/`GetDirectories` methods are necessary in these active-modification scenarios because they create a full snapshot before the modifications begin.
**Action:** Only apply `Directory.EnumerateFiles`/`Directory.EnumerateDirectories` optimizations to read-only traversals (e.g., `PermissionRepairer.cs`). Leave `GetFiles`/`GetDirectories` alone when the loop modifies the directory structure to avoid fatal regression bugs.
